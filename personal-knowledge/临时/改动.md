
## 1. 新增文件夹

这些目录在 3.1 里没有，可以整夹复制。它们不替换 Windows 的 `bin`。

| 文件夹                          | 作用                                              | 怎么放                                          |
| ------------------------------- | ------------------------------------------------- | ----------------------------------------------- |
| `DHL-Test-Windows/src/platform` | 按系统区分 dll/so、日志目录、注册表和配置文件路径 | 整夹拷进 3.2 的源码                             |
| `Install/DHL-Test-Fusion`       | Linux 安装包                                      | 整夹拷到仓库里，不要覆盖 `DHL-Test-Windows/bin` |

`Install/DHL-Test-Fusion` 里面主要是这些子目录：`qml`（约 1055 个 Qt 界面文件）、`lib`、`plugins`、`PrintLibs`、`BoxLibs`、`firmware`、`Logs`、`check4GModel`，以及 `run2.sh`、`qt.conf`。这是给 Linux 柜子用的运行环境，Windows 编译不依赖它们。

拷完先编 Windows。这一步还没改旧源码，结果应和 3.1 一样。

## 3. 改动过的 C++ 文件

这些文件 3.1 里已经有了。不要用 lvjiahao 的文件整份覆盖。打开补丁里对应的一段，只把 Linux 或 Fusion 的分支合并进 3.2 的原函数。Windows 那一段保持 3.1 原文。

建议按这个顺序，每组编一次 Windows。

**第 1 组，只换路径，Windows 仍用原来的 dll 和 exe**

- `src/utils.cpp`：日志目录 Windows 仍是 `c:/SNBC/HWTest/Logs`
- `src/loader.cpp`、`src/loader.h`
- `src/logger.cpp`：Windows 控制台日志仍带级别
- `main.cpp`：Windows 仍叫 `DHL-Test-Windows`，版本仍从 exe 的 3.1.0.0 读
- `global.h`

**第 2 组，硬件库按系统分开**

- `src/cabinetlib.cpp`、`src/cabinetlib.h`：Windows 仍加载 `CSMW.dll`。开全部格口、查全部状态仍走原来的 `openAllCabinetBox`、`getAllCabinBoxOnOffStatus`

- `src/upgradeprocess.cpp`、`src/upgradeprocess.h`、`src/firmwareinterface.cpp`、`src/firmwareinterface.h`：Windows 仍用 `UpgradeTool.exe`

**第 3 组，音频、键盘、网络**

- `src/microphoneinterface.cpp`、`src/microphoneinterface.h`

- `src/functionkeymonitor.cpp`、`src/functionkeymonitor.h`
- `src/hidkeyboardmonitor.h`

**第 4 组，菜单和柜型。这里最容易把 Windows 改坏**

- `src/lightinterface.cpp`
- `src/compartmentinterface.cpp`
- `src/advancedinterface.cpp`
- `src/testinterfacebase.cpp`、`src/testinterfacebase.h`：lvjiahao 把一部分测试项只在非 Windows 上隐藏。这段可以要，Windows 不要隐藏
- `src/reportinterface.cpp`、`src/reportinterface.h`：Windows 保存报告时，目录不存在就失败，不要改成自动建目录

`DHL-Test-Windows_resource.rc` 在补丁里被删了。3.2 上留着它，不要删。窗口标题还靠它生成 3.1.0.0。

## 4. 改动过的 XML

补丁里没有修改任何旧的 xml，只有两个新增文件：

- `DHL-Test-Windows/DHL-Test-Windows.xml`
- `Install/DHL-Test-Fusion/DHL-Test-Windows.xml`

它们是某次运行生成的测试记录，里面仍是 3.1 的测试项，另外多了两个属性：`testServerIp="2.253.244.27"` 和 `productionServerIp="165.72.1.26"`。不要用这两个文件覆盖柜子上已经测了一半的 xml，否则上次进度会丢。

真正要合并的是读写代码：

- `src/xmlparser.cpp`
- `src/xmlparser.h`

合并时只要这两点：没有这两个 IP 属性时，仍使用原来的 `2.253.244.27` 和 `165.72.1.26`。Windows 生成的测试项名称、可测和置灰，仍由 3.1 的 `itemdata.cpp` 决定，不要把 lvjiahao 菜单写进 Windows 的 xml。

Linux 安装包里的那份 xml 随 `Install/DHL-Test-Fusion` 一起拷贝即可，它只给 Linux 包用。

## 建议的操作节奏

1. 先拷新增文件夹和新增文件，登记进 `unix` 工程，编 Windows。
2. 再按第 1 组到第 3 组并 C++，每组编一次 Windows。
3. 最后并 `itemdata`、`globaldef`、`deviceinfointerface`、`xmlparser`。这一组做完后，用 Windows 的 ISA 看首页：柜型仍显示 ISA，PODID 仍在，固件页仍有 BIOS 和收据打印机。
4. Linux 能编过后，再在 Linux 上接电池页、环境光和 Fusion 柜型。这些不要先接到 Windows 菜单上。
